# 模块职责与扩展规则

本文定义新代码应遵循的职责和依赖方向；它不要求立即重构当前原型实现。实际结构和已知例外见 [architecture.md](architecture.md)。

## 总体方向

运行时依赖保持为：

```text
main → presentation → core
```

| 模块 | 负责 | 可以依赖 | 不承载 |
| --- | --- | --- | --- |
| `main` | 浏览器和 Phaser 启动装配 | `presentation`、启动配置 | 游戏规则 |
| `presentation` | 输入翻译、视图、摄像机、DOM、运行时装配 | `core`、Phaser、DOM | 资源、战斗、建造等业务不变量 |
| `core/commands` | 接受意图、验证规则、推进任务 | ECS、地图、核心配置、模拟 interface | 渲染和 DOM |
| `core/ecs` | 状态结构、世界创建、实体生命周期 | 核心配置和纯数据类型 | 场景和 UI 状态 |
| `core/map` | 坐标、障碍、通行性和寻路 adapter | 寻路库 | 实体表现和玩家输入 |
| `core/simulation` | 可替换的模拟策略 interface | 核心世界和纯类型 | Phaser 对象 |
| `tests` | 通过被测 interface 验证可观察结果 | 被测模块 | 以私有实现细节作为主要断言 |

核心规则应在没有 Phaser、Canvas 或 DOM 的环境中执行和测试。表现层可以读取核心状态并发出意图；新的核心状态转换应集中在命令、系统或实体生命周期函数中。

## Interface 与复杂度

- 一个 module 对调用方暴露一个尽量小的 interface，并在内部隐藏规则组合和第三方库细节。
- 只在行为真实变化时建立 seam；生产 adapter 与测试替身可以构成真实变化点。
- 共享状态不通过新增全局单例扩展；优先显式传入世界、地图或所需依赖。
- 新功能若需要在 `GameScene` 中加入状态机、资源结算、战斗判定、建筑合法性或其他业务规则，应先把规则放入 `core`，场景只负责调用和呈现。
- `GameScene` 的现有职责不在本轮重构。后续改动若同时增加两个以上互不相关的职责，先提交拆分影响分析。

## 状态所有权

- ECS 拥有实体及其游戏状态；修改应经过拥有该规则的核心 interface。
- `GridMap` 当前拥有阻塞格。建筑系统加入前必须确认地图占地与建筑实体之间的权威来源和同步方式。
- 表现层拥有选择、镜头、面板开关和绘制对象等瞬态状态，不把这些状态写入核心，除非它们成为可保存的游戏规则。
- `GameInputController` 只拥有当前中键拖动手势；选择、地图编辑和命令解释仍由 `GameScene` 装配，不在输入 module 中复制玩法规则。
- Developer Console 使用与正常玩法相同的核心 interface；确需绕过时，将绕过限制在可识别的调试路径并补充验证。

## 扩展方式

### NPC 与单位

新增类型时扩展实体数据和核心行为，不增加 `worker2`、`specialNpc` 一类世界特殊字段。表现层根据核心数据选择外观，不以外观反推规则。

### 资源与经营

资源类型、库存和生产规则属于核心。命令引用实体或稳定标识；UI 只显示状态和提交意图。现有单资源配置是当前实现，不是长期接口。

### 建筑

放置、占地、建造进度和产出属于核心。实现前先解决 ECS 与 `GridMap` 的占地所有权；渲染对象不作为建筑存在性的依据。

### 战斗

目标选择、伤害、冷却、死亡和阵营规则属于核心；动画、音效和命中特效属于表现层。战斗 Tick 与移动/采集的顺序需要先形成明确设计。

### 寻路与避让

`findPath` 保持第三方寻路库的窄 adapter。改变方向规则、净空、动态重寻路或群体避让会影响移动 interface 和确定性，按重大变更处理。

## 重大变更流程

公共 interface、ECS 数据模型、状态所有权、寻路语义或依赖方向变化前，先给出：

1. 当前行为与目标行为；
2. 受影响的 module、调用方和数据；
3. 兼容性、迁移和回退风险；
4. 自动化与手工验证范围；
5. 需要同步的架构文档或决策记录。

获得确认后再修改实现。局部实现细节、同一 module 内的修复和不改变上述契约的测试可以直接完成。

## 当前例外

- `GameScene` 直接执行世界重置、验证场景和部分组件写入。
- `gameWorld` 包含领袖、工人、单一资源点和单一仓库的特殊引用。
- `cameraConfig.ts` 位于 `core/config`，但属于表现配置。

这些是当前原型已记录的例外，不是新代码应继续扩散的模式；处理它们需要独立任务和影响分析。
