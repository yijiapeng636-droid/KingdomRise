# 《王国崛起》开发版本规划 V2.0

> 规划版本：V2.0  
> 更新日期：2026-10-13  
> 当前阶段：V0.2 稳定性收尾

> 版本口径说明：这是一次追溯性里程碑重划分。仓库初始提交及 2026-10-12 的开发总结曾使用旧口径，将部分采集、运输和调试能力记入 V0.1；相关历史记录保留原貌。自本规划起，V0.1 固定为基础 RTS 地图原型，后续已开发能力统一归入 V0.2。

## 1. 版本调整原则

项目目前已经实现了比原始 V0.1 更多的功能，因此重新定义后续版本范围。

本次调整遵循以下原则：

1. 固定本规划定义的 V0.1 范围，不再向历史版本追加新需求。
2. 将已开发的采集、运输、多单位基础和调试系统归入 V0.2。
3. V0.2 以稳定性验证、问题修复和文档整理作为收尾重点。
4. 后续每个版本都必须提供可以实际体验和测试的新能力。
5. 每个版本明确功能范围、验收标准和暂不实现的内容。
6. 不因开发便利而提前引入复杂系统，避免版本范围不断扩大。

## 2. V0.1：基础 RTS 地图原型

**版本定位：历史基础版本**

目标：验证地图、角色控制和寻路系统是否能够正常运行。

功能范围：

- 网页游戏工程及 Phaser 场景。
- 四边形正交方格地图。
- 领袖实体及角色状态。
- 鼠标选择与移动命令。
- A* 寻路及障碍判断。
- 游戏镜头平移和缩放。
- 基础 HUD 信息显示。
- 核心逻辑的自动化测试。

验收目标：玩家可以选择领袖、控制移动并绕过地图障碍。

此版本不包含采集、运输、建造和多单位经营。

## 3. V0.2：采集运输与核心模拟系统

**版本定位：当前开发阶段，进入稳定性收尾**

目标：在 V0.1 基础上，实现可以自动运行的最小资源采集与运输循环，并提高核心系统的可靠性。

### 已开发功能

- 多个角色独立接受操作。
- 连续世界坐标移动及安全斜向寻路。
- 静态障碍路径裁剪和逐 Tick 净空校验。
- 单一木材采集链路（单资源点、单仓库）。
- 单位携带容量。
- 自动运输和仓库交付。
- 多单位共享资源及仓库。
- 固定步长模拟、暂停、单步和倍速。
- 开发者面板及交互式验证场景。
- 可拖动悬浮面板。
- 镜头平滑缩放、边界控制。

### 当前剩余工作

主要开展稳定性检查，不再增加大型业务系统。

1. 对移动路径及静态障碍碰撞进行回归测试。
2. 补齐资源耗尽、采集路径阻断和近满仓并发交付等边界回归。
3. 检查多个角色同时采集时的数据一致性。
4. 验证悬浮面板、镜头缩放与地图操作不存在冲突。
5. 确保自动化测试、TypeScript 检查和生产构建通过。
6. 同步代码、架构文档、操作说明和版本记录。

### V0.2 完成标准

玩家可以分别控制多个角色，使其自动执行采集、运输和仓库交付；系统可以正确处理资源耗尽、仓库满载和无法到达的目标，且关键业务流程可以重复验证。

### 不纳入 V0.2

- 多单位框选和群体指挥。
- 完整的单位动态避让。
- 多资源生产链。
- 建筑放置及施工。
- NPC 智能决策。
- 实时战斗和装备系统。

## 4. V0.3：多单位 RTS 操作系统

**版本定位：下一阶段重点开发**

目标：从单个角色的独立操作，升级为真正的多单位 RTS 操作体验。

### 功能范围

#### 多单位选择

- 鼠标框选单位。
- Shift 多选或取消选择。
- 显示当前选中的全部单位。
- 清晰区分领袖和普通居民。

#### 群体指令

- 通过一次操作对选中单位统一下达移动指令。
- 群体中的多个单位可以同时执行同一移动指令。
- 玩家能够中断或替换选中群体的当前命令。
- 防止多个单位无条件挤向同一个目标点。

#### 基础单位避让

- 实现简单的单位分离避让。
- 处理单位之间的重叠。
- 避免绕过动态单位时穿越静态障碍。
- 验证窄路、交叉移动和同目标聚集等场景。

#### 状态反馈

- 汇总显示多选单位的待机、移动、采集和运输等任务状态。
- 对无法执行的命令提供明确反馈。
- 完善多单位状态显示和开发者调试能力。

### 完成标准

玩家可以框选多个居民，一次性下达移动命令。单位能够完成群体移动，不会因为简单拥堵而持续卡死，也不会穿越障碍。

本版本暂不实现复杂军队阵型、战斗编队、ORCA 大规模避让及高级 NPC AI。

## 5. V0.4：建筑与资源扩展系统

目标：从单纯采集运输发展为初步建设领地。

功能范围：

- 支持至少两种资源，例如木材和粮食。
- 支持多个资源点。
- 支持选择和放置建筑。
- 建筑占地与地图障碍联动。
- 建筑消耗资源。
- 居民可以执行施工任务。
- 建筑具备建造中和已完成状态。
- 实现至少一种具有实际作用的建筑。

完成标准：玩家可以指挥居民采集资源、运输资源、消耗资源并完成建筑施工，形成完整的“采集—运输—建造”循环。

## 6. V0.5：最小生存经营系统

目标：让领地拥有可持续运行的经营规则。

功能范围：

- 居民人口基础管理。
- 居民基础食物消耗。
- 资源生产和消耗平衡。
- 基础工作分配与自动执行。
- 建筑提供实际经营作用。
- 资源不足产生明确的负面影响。
- 玩家可以通过调整生产和建设改善领地状况。

完成标准：玩家不仅可以建造领地，还需要持续安排生产，以维持居民生存和领地发展。

## 7. V0.6：基础实时战斗系统

目标：实现领地受到威胁时的实时作战。

功能范围：

- 敌对单位。
- 攻击和追击命令。
- 生命值、攻击力和伤害。
- 攻击范围与攻击冷却。
- 单位死亡。
- 基础敌对行为。
- 简单的领地防卫战斗。

完成标准：玩家可以指挥领袖和居民组成的基础自卫队，击败一次敌对遭遇，并能够正确处理伤害和减员。

此阶段暂不实现复杂装备、技能、俘虏和大规模军团系统。

## 8. V0.7 及后续版本

根据前面版本的实际体验，逐步安排：

- 居民能力、等级和职业系统。
- 人事任免及岗位加成。
- 忠诚度、繁荣度与居民行为。
- 商队、店铺和贸易。
- 领地扩张。
- 世界地图探索与随机事件。
- 更智能的 NPC 行为。
- 战争、外交与领地竞争。
- 存档、移动端适配及后续发布。

这些属于长期目标，具体版本不提前固定。

## 9. 版本交付规范

每个版本必须满足：

1. 所有承诺的核心功能都有可验证的运行结果。
2. 核心逻辑具备相应自动化测试。
3. 通过项目类型检查与构建。
4. 完成必要的浏览器交互测试。
5. 更新开发文档、架构记录及已知问题。
6. Git 提交清晰，能够定位和回退改动。
7. 明确记录未完成或推迟的任务。

版本范围确定后，不随意增加新功能。确需增加的内容先评估影响，再决定是否调整计划。

## 10. 当前开发决策

当前项目正式进入 V0.2 收尾阶段。

短期不再增加建筑、战斗或 NPC AI 等大型系统，优先完成现有移动、采集、运输和开发调试功能的回归验证。

V0.2 验收通过后，进入 V0.3，重点实现多单位选择、群体指挥和基础单位避让。

所有技术开发继续遵循已有架构约定：游戏规则位于 `core`，Phaser 和 DOM 负责表现，避免将新的业务逻辑持续堆积到 `GameScene` 中。
